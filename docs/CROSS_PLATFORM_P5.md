# P5：跨平台 MME 实施计划

日期：2026-11-05。代码核查基线：`main@c6125a0`。

**状态：P5.1／P5.2 已在各自明确支持范围通过三平台验收；P5.3—P5.5／C2 尚未完成。** 用户同意 P4 阶段放行，真实
混合 DPI 跨屏实测延后；该未测项仍记录在 [P4 验收表](P4_ACCEPTANCE_STATUS.md)，
不再阻挡 P5 开始。

## 目标

Windows、macOS、Linux 在没有 DX9／D3DX 效果对象的情况下，直接读取原始 `.fx`
及其 include，执行明确支持的材质、场景和子效果链。Qt 编辑器和离屏导出消费相同
的当前帧效果快照；效果切换、参数修改、窗口缩放及后端替换保持一致的执行语义。

P5 的完成条件是 **C2：公开、明确的 MME 子集在三平台实际运行通过**。完整 Ray、
任意历史效果和 Windows 二进制插件兼容不属于这项承诺。Ray 作为实际需求和缺口
探针持续使用，完整链路仍按 P7／C3 单独验收。

## 核查结果：已有基础与真正缺口

| 部分 | 当前实际状态 | P5 需要做什么 |
|---|---|---|
| RHI | DX11／DX12／Vulkan／Metal 已有通用 VS／PS、16 槽纹理／采样器、MRT、RGBA16F、自阴影、mip 与后处理 | 复用现有能力，按效果实际需求补能力，不重新实现后端 |
| FX9 源码解析 | `third_party/mmeffect/src/mme_legacy_source.cpp` 可无设备解析已展开源码并生成现代 HLSL | 补齐源文件加载、预处理、完整元数据、默认值和来源信息；不能只接收原生引擎事先展开的文本 |
| 标准参数和脚本计划 | `mme_standard_parameters.cpp`、`mme_scene_plan.cpp` 已有纯 CPU 实现与测试 | 变成生产目标的共用依赖，接入跨平台实例、参数池和宿主上下文 |
| 效果加载与 SAS | `effect_engine.cpp` 先创建 `ID3DXEffect`；`SasParse`、`mme_portable.cpp` 从原生对象读取参数、注解、命令及共享纹理 | 建立不含 COM／D3D 类型的权威描述，原生效果对象只作为 Windows 对照或适配器 |
| 效果到 RHI | `src/render/mme/portable_effect.cpp` 已将有限效果转换为 `RenderFrame` | 仍直接依赖 `D3DPreprocess`、`D3DCompile`／`D3DReflect`、WRL、D3DX 数学及旧宿主全局状态；需拆出可移植装配器 |
| 构建边界 | 上述装配器属于 `mikudancestudio_core`，位于 formats-only 和非 Windows 提前返回之后 | Qt 构建使用独立 portable-editor 入口，没有链接完整 MME 引擎；须显式提供跨平台 MME 生产库 |
| Qt 与会话 | `EditorSession`、Qt 前端和 `SceneFrameProducer` 尚无用户 MME 分配／实例管理接入 | 补效果服务、分配／参数编辑、兼容性诊断、保存重开及帧构建／导出接入 |
| Ray | 历史原生记录有屏幕效果 31 个 Buffer Pass、39 个纹理参数、s0..s12；MaterialMap 子效果已有有限 RHI 证据 | 不把子效果通过当作完整 Ray。根效果已记录首个阻断为计算型非 const static 初始化，其他语义仍须逐阶段检查 |

本轮本地复跑 `mme_legacy_source`、`mme_standard_parameters`、`mme_scene_plan`：
**3/3 通过**，未创建窗口。该结果只证明现有三个 CPU 构件可作为基线，不能代表
完整效果导入或三平台 MME 已运行通过。

## 目标数据流与模块边界

```text
原始 FX／include／宏／编码／来源图
                  ↓
不可变 EffectDefinition（声明、默认值、注解、技术、Pass、脚本、资源）
                  ↓
EffectInstance ＋共享参数池＋当前 SceneRuntime／材质／时钟上下文
                  ↓
当前帧参数快照＋技术选择＋有序效果执行计划
                  ↓
RenderFrame／ShaderProgram → Null／DX11／DX12／Vulkan／Metal
```

`EffectDefinition`、`mikudancestudio_mme_frontend` 与 `mikudancestudio_mme_runtime`
已建立，旧 Windows 引擎链接共用 CPU 实现。Qt 的实例／装配接入仍按后续批次推进。
公共接口使用固定宽度类型、稳定 ID、不可变字节和显式上下文，不能包含
`ID3DXEffect`、`D3DXHANDLE`、HWND、COM、`MMDApp` 或编辑器全局对象。

`portable_effect.cpp` 按源码／着色器布局、参数绑定、材质装配、场景／子效果调度
拆分，保持一个模块一种职责。现有 SAS 算法按边界提取到共用实现；旧路径通过
适配器调用。提取期间逐项差分，不另写长期并行且含义不同的脚本解释器。

## 实施批次

### P5.1：独立源码前端与可对照描述

本批实现、支持边界和验证入口见 [无设备源码前端](MME_FRONTEND.md)。默认值目前
保留表达式，实际求值与实例初始化属于 P5.2。原生元数据参考改用无设备的
`ID3DXEffectCompiler`／`ID3DXBaseEffect`；绘制对照仍在 P5.4 验收。
最终定向 CI [42020565345](https://github.com/jstzwj/MikuDanceStudio-NG/actions/runs/42020565345)
通过 Windows 8、Linux 7、macOS 7 项；下载产物中的完整语义描述严格一致，见
[版本化证据](evidence/p5-frontend-42020565345.json)。初轮错误和修复后的补验分别保留。

首批拆成三个可审查提交：

1. **独立效果定义与构建边界。** 把现有无平台源码解析、标准参数、脚本计划组织为
   生产库；效果定义保留参数类型／数组／默认值、注解、共享标志、技术／Pass 和
   资源声明。未知语法给出文件、行列、声明、技术／Pass 与失败阶段。
2. **FX9 源加载及元数据。** 加入有来源映射的 include／宏预处理、编码和相对路径
   解析，保留 `_INDEX=PSIZE15`、`MME_MIPMAP` 等实际宏语义。固定 include 搜索顺序、
   循环／深度／大小限制；不通过修改进程 cwd 影响其他加载。默认值和注解从源码
   得到，不能再靠 D3DX 查询。预处理工具选型先比较与现有 DX9 的宏展开结果，
   不能因已有 DXC 就假定它能正确处理全部 FX9 源码。
3. **无窗口导入 CLI 与 Windows 对照。** 建议新增 `mds_effect_cli inspect`，从原始
   `.fx` 输出稳定 JSON 描述和分阶段诊断，增加依赖审计。公开生成夹具在三系统
   对比声明／默认值／技术／Pass／脚本结果；Windows 隐藏原生对照程序另读
   `ID3DXEffect`，不能用新解析器同时生成参考和实际值。

退出条件：无 DX9 设备即可从原始、无专用注解的材质和场景文件得到完整的首批
效果描述；缺 include、循环、截断、未知状态等明确失败。三平台结果一致，
Windows 原生元数据对照通过。这里只承诺描述／导入，不把它当作渲染通过。

### P5.2：参数实例、共享池与语义

实现与支持边界见 [参数运行时](MME_RUNTIME.md)。2026-11-06 的定向 CI
[42168010475](https://github.com/jstzwj/MikuDanceStudio-NG/actions/runs/42168010475)
通过 Windows 12、Linux 10、macOS 10 项门禁；下载产物的完整参数描述／默认值和逐绘制
帧快照一致，[版本化证据](evidence/p5-runtime-42168010475.json)保留组件值、哈希和产物身份。
本地旧 Windows SAS 控制参数适配器也单独编译通过。Windows 的独立参数参考使用 NULLREF
和自有隐藏窗口，不进行绘制或 Present；另外两平台纯 CPU，无窗口／设备。

P5.2 在上述数值／字符串参数和已声明语义范围验收通过；纹理共享身份、脚本写回及 Qt
实际效果消费继续属于后续批次，不能把本次参数测试记为完整 MME／C2 已运行通过。

- 不可变定义与可变实例分离；克隆仅共享定义，共享参数按原生类型／名称／生命周期
  规则进入池，不因值或纹理名字碰巧相同就合并。
- 迁移默认值、运行期写入、共享值加载顺序、标准矩阵／灯光／材质／视口语义、
  `CONTROLOBJECT` 及 TIME 系列。使用已验收 CPU 数学，保留矩阵布局与存储边界。
- 每帧时钟只采样一次，每次绘制参数冻结；准备失败后不得提前提交循环索引、
  参数池写回或屏幕历史。暂停、拖动、重试不能重复推进动画／物理。
- 从旧参数池／SAS 执行顺序中确认实际写回点，不预设所有脚本写入都等到帧末。

退出条件：多实例共享／非共享、控制对象存在／消失、参数类型冲突、加载卸载及
失败恢复均有 CPU／Null 门禁，结果与 Windows 独立参考一致。

### P5.3：脚本、分配及跨效果资源调度

- 迁移技术选择、MmdPass／Subset／纹理条件、显式空覆盖、场景显示顺序、
  `ScriptExternal`、`Draw=Buffer`、循环、`DefaultEffect`、嵌套子效果。
- 共享目标使用稳定发布者身份与代次；维持相对尺寸、格式、初始化、读写依赖、
  父子作用域、卸载重建和整轮结束后的 mip 时点。复用现有 `RenderFrame` 校验。
- 确认 `.emm` 对象／材质分配及路径规则，形成平台无关文档；普通自动同名效果
  和显式覆盖共用分配服务。未确认格式前不把效果信息硬塞进 PMM 原版块。
- 输出可重复的执行报告：对象／子集、技术、Pass、共享资源 ID、读写及 mip 操作。
  先完整检查计划，再触发 GPU 提交；非法反馈／未初始化／过期引用必须拒绝。

退出条件：公开的材质＋两级场景＋子效果链通过 CPU／Null 顺序与生命周期对照，
不依赖原生 SAS 对象才能生成计划。沿用既有支持边界，扩展必须单独验收。

### P5.4：着色器布局及四后端执行

- 通用 HLSL 及绑定描述从同一效果定义产生。跨平台反射／布局接口不暴露 COM，
  验证常量偏移、矩阵、数组、bool、VS／PS 接口、16 槽绑定、MRT 输出和采样设置。
- 可移植装配层不再为查询布局调用 D3DCompile。Windows DX11／DX12 的原生后端
  适配器仍可使用其现有编译器；Vulkan／Metal 复用 DXC SPIR-V 与 SPIRV-Cross，
  不强求 DX11 直接接受 SM6 或 SPIR-V。
- 缓存包含冻结源码及 include 内容、宏、前端版本、入口、编译器身份／版本／策略、
  后端与布局。修改任一依赖应失效；编译失败也按修订缓存，重载可恢复。
- 用同一公开材质、场景后处理、共享目标／MRT／HDR／相对尺寸／mip／子效果夹具，
  覆盖四后端运行、缩放、设备替换、重复提交及卸载重载。

退出条件：原始 FX 到实际 GPU 输出完整走通，三平台无 D3DX 生产依赖；编译成功
与资源／脚本／图像通过分别记录。严格复制、重复与生命周期契约继续保留；浮点
和整帧视觉采用已经确认且明确适用范围的标准，不把视觉标准用于豁免错误绑定。

### P5.5：Qt 编辑器、保存与发布闭环

- `EditorSession` 管理无 GPU 的效果分配与可编辑参数，渲染服务持有编译／设备资源。
  Qt 提供分配、开关、重载及兼容性报告，并沿用 15 语言翻译机制。
- 效果经过同一个 `SceneFrameProducer`／共享帧装配边界进入视口与图像序列导出；
  明确生成帧、提交成功与状态写回的事务，保持一次 CPU 场景更新。
- 保存、另存、重开保留已声明的效果引用与路径；模型删除、材质变化、撤销重做、
  后端切换与语言切换不能产生悬空实例或丢失分配。
- NG Qt 不是旧 Win32 编辑器，不能假定它有自动 DX9 整帧回退。不支持的效果明确
  报告原因；用户可显式选择基础材质降级。旧 Windows 宿主已有的同帧 DX9 回退保留。
- 三平台干净发布包直接加载自带公开 FX，检查工具、include、缓存、重定位与错误
  恢复；常规帧不以回读实现呈现。

退出条件：打开工程→分配效果→编辑参数→播放／拖动→切后端→保存重开→导出
在三平台通过；受支持效果完整执行，失败没有旧画面冒充成功或重复场景更新。

## C2 验收矩阵

| 层次 | 必须取得的证据 |
|---|---|
| 无 GPU 前端 | 原始文件、include／宏、编码、注解、默认值、状态和准确诊断；依赖图无原生效果对象 |
| 实例与语义 | 共享池、控制对象、矩阵／材质／灯光／时钟、脚本写回与加载卸载的独立对照 |
| 执行计划／Null | 材质／场景／子效果顺序，资源身份、尺寸、格式、初始化、别名、mip 和失败原子性 |
| GPU | Windows DX11／DX12／Vulkan、Linux Vulkan、macOS Metal；受支持链路的附件／整帧、缩放、重建与严格重复 |
| Qt／发行包 | 分配／参数／保存重开／导出／后端切换的闭环，无 D3DX 的干净环境加载；多语言不改变业务状态 |
| Ray 与其他真实效果 | 本地外部路径导入，按解析／语义／编译／资源／计划／执行分别报告支持或首个缺口，不复制第三方素材进发行包 |

只在相关代码变更时运行对应门禁；本地始终离屏／隐藏窗口，真实交互留给隔离 runner。
一次实现批次合并后做一轮需要的平台 CI，不以连续全量 dispatch 代替本地定位。
