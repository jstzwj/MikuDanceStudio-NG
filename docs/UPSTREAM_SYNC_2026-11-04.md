## 合并边界

- 不替换 Qt 前端、CPU 场景运行时、共享 RHI、后端设置和发行目录规则。
- `d3dx_dyn.hpp` 改名为 `d3dx_api.hpp`，同步 NG 独有的测试和适配器。D3DX 仍只属于 Windows 兼容边界。
- PMX 的主 VB、描边 VB 和 IB 创建均直接写入模型拥有的字段；即使 API 返回非零 HRESULT 并写回资源，失败路径也由统一析构释放。
- DX9 创建/索引锁定沿用来源审计的 `D3D_OK` 精确判定，顶点锁定沿用有符号 HRESULT 判定。CPU-only 加载不创建 DX9 资源。
- 保留 NG 的短读、文件格式校验和零骨骼处理；来源的实际骨骼数分配不能引入零长度数组写入。
- 保留异常输入的防护：附件父模型索引/空骨骼表不越界；SM2 编译失败且效果指针为空时不解引用。设备能力查询的输出先清零，正常成功路径仍使用来源的调用和 HRESULT 清理规则。
- Qt 的菜单生命周期修复保持生效。加载 PMD/PMX 后反复切换三种语言的隐藏测试同时检查选中骨骼标题。
- 已选中骨骼但英文名称为空的 PMX 仍绘制分隔符，与原版标题格式串的行为一致。
- 修复 NG 提取共享寻帧内核后失效的独立测试：显式注入曲线和物理通知服务，继续执行同一寻帧算法；生产使用原有默认服务。保留 880 个状态案例的原始哈希，以及独立的浮点位模式/负零预期，不重新生成金标准。
