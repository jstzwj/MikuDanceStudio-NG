# 多行 EDIT 的点击定位

当前实际输入结果（2026-11-05）：[41870574500](evidence/p4-active-41870574500.json)
在隔离 Windows 显示会话执行三语言的 **90 次 OS 点击、正反向拖选、Shift 点击和
双击选词**，原版与 Qt 的选择结果全部相同，按下前端点命中也相同。确认原生焦点、
鼠标捕获及消息实际送达，不将直接分发的合成事件作为该资格。
客户区外拖选自动滚动和复杂 Unicode 仍需独立对照。

生产控件在 ASCII／非预编辑路径保留原版命中位置，明确保存拖选锚点并应用
原版双击字词边界；非 ASCII／预编辑沿用 Qt。下文关于只调整事件坐标和由 Qt
独自维护锚点的描述属于早期实现，已由 `8014411` 更新。

后续 `b5502a9` 增加 **744 个双向拖选**比较：从原版冻结数据读取两个
独立命中位置，向真实生产控件发送按下／移动／释放，检查有方向的选区锚点
与当前位置。本地全部通过，同一运行保留 50,232 个命中和 509 个直接 Shift
点击检查。这些是从未显示的控件事件，不替代实际 OS 鼠标捕获／拖选资格。

原版英／日模型备注资源为 `666/665`，控件 `668`。新增观察器只映射 SHA-256
`07516fd3bf1e6b1339836b6773a156f61bdd6f848eeb621fdda012375df313a1`
的原版资源，创建从未显示的对话框，再读取 `EM_CHARFROMPOS`。没有鼠标注入、
捕获、焦点、激活或屏幕读取操作。生成命令：

```powershell
python tools/observe_multiline_layout.py --original <原版64位MMD.exe> --hit-test --output tests/reference/original-multiline-hit.json
```

冻结数据覆盖两种字体、六种 ASCII 文本和客户区三像素网格：普通文本、多行数值、
空行／首尾空格、Tab、超宽行及超高文档。Windows QPA 在三种 UI 语言中重放
**50,232** 个命中位置。中／日界面使用同一原版日文资源几何；这并不把原版 ANSI
控件的非 ASCII 数据丢失当作必须复现的行为。

原始 Qt 路径有 **15,596** 个差异。简单限制首尾行的 Y 范围后仍有 **495** 个差异，
因此修复没有停留在测试端坐标修饰。生产控件的共享命中函数现在使用 Qt 实际文字
布局，保留原生 EDIT 在首行上方／末行下方的水平位置，并把精确半字符位置判给后
一个光标。Qt 原有字形与行高不变，非 ASCII／预编辑继续使用 Qt 的原有处理。

控件只在 Qt 原有命中与新位置不一致时调整局部事件坐标，Qt 继续处理选择锚点、
Shift 选择、文字提交和拖动状态。测试另向**从未显示的自有只读 viewport**直接发送
475 组 Shift 点击事件，检查真实控件的 anchor／cursor；不发送系统输入，不移动
桌面鼠标，也不请求软键盘。50,232 个命中和 475 个选择比较均通过。

这个结果补齐多行**命中和直接事件分发**范围。它没有验收实际显示态的多行绘制、
捕获、双击选词、自动滚动拖选、Unicode／双向文字或真实跨屏 DPI；这些仍列在
[P4 当前验收表](P4_ACCEPTANCE_STATUS.md)。此前 438 个多行文字／Tab 几何及 864 个
多行上下／翻页比较保持独立门禁。
